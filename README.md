# release-stack

Build, test and release the Solid, Attest and LogoFX package stack as rc packages, so a fix can be proven in a consumer before anything reaches nuget.org.

Design: `docs/superpowers/specs/2026-11-11-rc-stack-design.md`. Plans: `docs/superpowers/plans/`.

## Commands

```
node src/cli.js rc [--from <repo>] [--ref <repo>=<ref>]...   build, test and pack the stack into the rc feed
node src/cli.js use --local <consumer>                         point a consumer at the latest rc
node src/cli.js use --stable <consumer>                        put the consumer back
node src/cli.js drift [--json]                                 table of every repo against the current stack (read only)
```

Environment: `DOTNET_ROOT=~/.dotnet-arm64 PATH=~/.dotnet-arm64:$PATH`. The rc feed is the `feed` in `stack.json`. `rc` builds from git worktrees and refuses repos with uncommitted changes to tracked files.

## Example

```
node src/cli.js rc --ref Solid=feat/reqnroll-adapter --ref Attest=feat/reqnroll-support
node src/cli.js use --local ~/Workspace/bdd-netcore
# run the consumer suite, no RestoreAdditionalProjectSources needed
node src/cli.js use --stable ~/Workspace/bdd-netcore
```

## Notes

- `RC_STACK_KEEP=1` leaves the temporary worktrees in place after a run, for debugging.
- `stack.json` is generated by `spikes/pack-parity/gen-manifest.js`. Two test projects are left out because they cannot run here: Solid `IntegrationTests.App` (fails on the unmodified branch) and Attest `Fake.FakeItEasy.Tests` (needs `netcoreapp3.1`). A known-failing allowlist is planned.
- Packages whose id differs from the project name are packed through their nuspec.
- Windows-only packages (`Solid.Common` platform variants) are skipped on macOS.
- The manifest names `Solid.IoC.Adapters.Reqnroll` and `Attest.Testing.Reqnroll`, which exist only on the PR branches until Solid#104 and Attest#119 merge. `rc --ref Solid=master` fails with "project not found" until then.
- A partial run (`rc --from X`) records the whole stack, carrying over the packages it did not rebuild, so `use` and later partial runs stay consistent.
- `drift` reads the manifest repos plus every git repo under the `scan` roots. The current stack is the latest rc record per family, or the latest stable of the family `anchor` on nuget.org when the record has none. Status: `current` (aligned and equal to the stack), `lagging`, `unaligned` (more than one own version, or more than one pinned version of a family), `none` (no family pins). A family whose stack version is unknown shows `?`.
- Known-failing tests: a repo in `stack.json` may list `knownFailing: [{ test, owner, expires }]` (`expires` is `YYYY-MM-DD`, still valid on that day). `rc` prints every entry on every run. A test run may fail only on listed, non-expired tests, and only if dotnet printed its totals (an aborted run is never allowed). An expired entry fails the run before anything is built, even if its test passes. Entries whose test passed are printed as `stale known failing`. `test` is the name as dotnet prints it after `Failed`.
